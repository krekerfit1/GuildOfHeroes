### Ответы на вопросы

#### 1. Чем отличается запрет внешней записи от проверки допустимого числа? Где проверяются здоровье при создании и его изменение?

`private set` определяет, **кто** может записывать значение только код внутри класса `Hero`, но он не проверяет, **какое число** записывает разрешённый код. Конструктор и методы находятся внутри `Hero`, поэтому запись им доступна, и проверки допустимых чисел написаны именно там:

- **При создании в конструкторе `Hero(string name, int health)`:** сначала проверяется и устанавливается личный предел `MaxHealth` (если `<= 0`, то `100`; если `> 200`, то `200`), затем текущее здоровье `Health` приводится к диапазону от `0` до `MaxHealth`:

  ```
  MaxHealth = health;
  if (MaxHealth <= 0) {
      MaxHealth = 100;
  }
  if (MaxHealth > 200) {
      MaxHealth = 200;
  }

  Health = health;
  if (Health < 0) {
      Health = 0;
  }
  if (Health > MaxHealth) {
      Health = MaxHealth;
  }
  ```
- **При изменении в методах `TakeDamage` и `Heal`:** `TakeDamage(int damage)` игнорирует неположительный урон (`damage <= 0`) и не опускает `Health` ниже `0`. `Heal(int amount)` игнорирует неположительное лечение (`amount <= 0`), вычисляет недостающее здоровье `int missingHealth = MaxHealth - Health;` и при `amount >= missingHealth` останавливает `Health` на границе `MaxHealth`.

#### 2. Как `Name = name;` связывает параметр конструктора, `value` и поле `_name`?

При вызове конструктора `new Hero("   Александр   ", 150)` данные проходят цепочку:
1. Аргумент попадает в параметр `name` конструктора.

2. Строка `Name = name;` обращается к свойству `Name` и запускает его закрытый `private set`.

3. Внутри `set` содержимое правой части присваивания `name` автоматически становится доступным через ключевое слово `value`.

4. При последующем чтении `alexander.Name` выполняется `get`, который возвращает проверенную строку из поля `_name`.

#### 3. Какие значения в проверках показали, что правило `0 <= Health <= MaxHealth` соблюдается?

- **Проверка нижней границы конструктора:** `new Hero("Проверка нижней границы", -100)` -> получено `0/100` .
- **Проверка верхней границы конструктора:** `new Hero("Проверка верхней границы", 5000)` -> получено `200/200`.
- **Обычные действия с Александром (`150/150`):** после `TakeDamage(30)` и `Heal(10)` здоровье стало `130`.
- **Большое лечение и отказ в отрицательном лечении:** `alexander.Heal(5000)` восстановило здоровье до личного предела `150`  а `alexander.Heal(-20)` было проигнорировано и оставило `150`.
- **Большой урон и последующее восстановление:** `alexander.TakeDamage(5000)` снизило здоровье до нижней границы `0`, а `alexander.Heal(20)` восстановило здоровье до `20`.

### ПР №3. Инкапсуляция собственного класса

Класс и его назначение:
`Game` — карточка игры в каталоге.

Какие данные защищены и почему:
`Title` без пустых строк и краевых пробелов, `Rating` строго от 0 до 10 и `Hours_Played` (не меньше 0) - чтобы нельзя было записать некорректные данные напрямую.

Какие свойства имеют private set:
`Title`, `Janr`, `Release_Year`, `Rating`, `Hours_Played`, `IsInstalled`.

Какое свойство использует закрытое поле:
`Title` поле `_title`: очищает пробелы через `Trim()` или ставит `"Без названия"`, если строка пустая.

Что проверяют конструктор и методы:
Конструктор ограничивает `Rating` рамками `0..10` и убирает минус у `Hours_Played`. `AddHours` принимает только `> 0` с защитой от переполнения `int`, `ChangeRating` проверяет диапазон `0..10`.

Проверки двух объектов и полученные результаты:
* `game1`: имя очищено до `"Witcher 3"`, часы `45 + 10 = 55` (`-20` отклонено), рейтинг `9.8` (`15.0` и `-5.0` отклонены).
* `game2`: остался без изменений (`8.0`, `10` ч.).
* `probeGame` (`"   "`, `15.0`, `-50`): скорректирован конструктором в `"Без названия"`, рейтинг `10`, часы `0`.
