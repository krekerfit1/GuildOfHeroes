## Практическая работа №7

1. Почему два признака bool хуже одного перечисления?
    - Два `bool` допускают невозможную комбинацию и выполнено и отменено, а для отличия "открыто" от "назначено" приходится смотреть ещё и на `AssignedHero`. Перечисление `enum` гарантирует ровно одно допустимое состояние.

2. Какие состояния поручения конечные и почему?
    - `Completed` и `Cancelled` - из них поручение уже не может перейти ни в какое другое состояние.

3. Куда делась проверка AssignedHero != null в Quest.TryAssign?
    - Она заменилась на `Status != QuestStatus.Open`, так как в состоянии `Open` исполнителя нет по определению.

4. Где хранится занятость героя?
    - Нигде не хранится — она вычисляется в `QuestBoard.IsAssigned` по списку поручений.

5. Почему проверку занятости нельзя делать после назначения?
    - `quest.TryAssign` успеет изменить состояние поручения, после чего `IsAssigned` увидит это же поручение и вернёт `false` - программа одновременно откажет и назначит героя.

6. Почему доска не даёт удалить Сергея?
    - На него ссылаются поручения в истории доски - удаление нарушило бы целостность истории.

**Трассировка:** прогноз `True, False, True, True, False, True, False, False, 10`, совпало.
Состояния поручений после каждого вызова:
- 1-я строка `True` — `Assigned` / `Open`;
- 2-я строка `False` — `Assigned` / `Open`;
- 3-я строка `True` — `Completed` / `Open`;
- 4-я строка `True` — `Completed` / `Assigned`;
- 5-я строка `False` — `Completed` / `Assigned`;
- 6-я строка `True` — `Completed` / `Cancelled`;
- 7-я строка `False` — `Completed` / `Cancelled`;
- 8-я строка `False` — `Completed` / `Cancelled`;
- 9-я строка `10` — `Completed` / `Cancelled`.

**Ошибка 1:** без проверки `quest.Status == QuestStatus.Assigned` ссылка в выполненном №101 осталась, и доска считает Сергея занятым навсегда.

**Ошибка 2:** `quest.TryAssign` сначала назначает героя, а потом `IsAssigned` находит это же поручение и возвращает `false`, оставляя изменение в силе.

**Самостоятельный шаг:** в `QuestBoard` добавлены `CountByStatus` и `FindActiveQuest`Ярослав — №104, Сергей — `null`. Переписан `IsAssigned` в одну строку через `FindActiveQuest`.

### Личный проект
В `PlaySession` свойство `IsFinished` заменено на перечисление `PlaySessionStatus` (`Open`, `Active`, `Finished`, `Cancelled`), добавлена отмена `TryCancel`. Таблица переходов:

| Сейчас | `TryStart` | `TryFinish` | `TryCancel` |
| --- | --- | --- | --- |
| `Open` | → `Active` | отказ | → `Cancelled` |
| `Active` | отказ | → `Finished` | → `Cancelled` |
| `Finished` | отказ | отказ | отказ |
| `Cancelled` | отказ | отказ | отказ |

Конечные состояния — `Finished` и `Cancelled`. Занятость игры не хранится в `Game`, а вычисляется в `GameLibrary.IsGameBusy` по активным сессиям, чтобы флаг не мог разойтись с реальным состоянием списка сессий.
