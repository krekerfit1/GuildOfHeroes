## Практическая работа №5
1. Кто теперь проверяет повтор при добавлении и почему не Program?
   - Повтор теперь проверяет сама гильдия в методе `AddHero`. Если оставить проверку в `Program`, любой другой участок кода сможет обойти правило и добавить дубликат.

2. Когда FindHeroByName возвращает null?
   - `FindHeroByName` возвращает `null`, когда запрос пустой или из одних пробелов либо когда ни один герой в списке не совпал по имени.

3. Зачем очищать запрос, если имена героев уже очищены?
   - Запрос приходит извне например, от пользователя и может содержать лишние пробелы по краям, поэтому его нужно очищать перед сравнением.

4. Почему MemberCount не хранит число, а вычисляет его?
   - Вычисляемое свойство `MemberCount` всегда возвращает актуальный `_heroes.Count`, и не нужно следить за отдельным счётчиком при каждом добавлении или удалении.

5. Удаление из гильдии уничтожает героя?
   - Нет, удаление убирает только ссылку на героя из списка `_heroes`. Сам объект остаётся жить, пока на него ссылается переменная снаружи.

6. Почему private-поле не защищено, если вернуть его из метода?
   - `private` скрывает только имя поля, но если метод возвращает ссылку на сам список `_heroes`, внешний код получает к нему прямой доступ и может его очистить или изменить.

### Личный проект
Ключ — название игры `Title`, так как в библиотеке игры обычно различают по названию. Ключ может подвести, если добавить ремейк и оригинал с одинаковым названием например, `DOOM` 1993 и `DOOM` 2016. Если игра не найдена, `FindGameByTitle` возвращает `null`, а `Program.cs` проверяет результат через `if (foundGame != null)` перед выводом.
