## Практическая работа №4

1. **Что хранит элемент `List<Hero>`?**
   Ссылку на объект `Hero`, а не его копию.
2. **Почему созданный через `new Hero(...)` объект ещё не в списке?**
   Создание объекта и добавление в список — разные действия; пока не вызван `Add(...)`, список о герое не знает.
3. **Чем `Count` отличается от последнего индекса?**
   `Count` — количество элементов, а последний индекс равен `Count - 1`, так как нумерация идёт с `0`.
4. **Что обозначает `hero` в `foreach (Hero hero in guild.Heroes)`?**
   Текущий элемент на каждом шаге цикла — ссылка на очередного героя из `guild.Heroes`.
5. **Почему урон через переменную виден и через список?**
   Переменная и элемент списка ссылаются на один и тот же объект в памяти, поэтому `TakeDamage` меняет его сразу для обоих.
6. **Что `private set` у `Heroes` запрещает, а что пока разрешает?**
   `private set` запрещает заменить сам список даёт `CS0272`, но позволяет получить его через `get` и менять содержимое через `Add`, включая добавление дубликатов.

**Трассировка:**

| Индекс | Ссылка ведёт к | Health после урона |
| ---: | --- | ---: |
| 0 | Первый | 70 |
| 1 | Второй | 80 |
| 2 | Первый | 70 |

Создано 2 объекта `Hero` (`first` и `second`); мой прогноз и фактический вывод совпали (`3`, `70`, `Первый: 70`, `Второй: 80`, `Первый: 70`, `Второй`), расхождений нет — индексы `0` и `2` ведут к одному объекту `first`, а `Count - 2` даёт индекс `1` (`second`).

**Ошибка 1:** причина — индекс `guild.Heroes.Count` выходит за границу списка, а проверка `Count > 0` защищает только от пустого списка; исправление — `guild.Heroes[guild.Heroes.Count - 1]`.  
**Ошибка 2:** причина — `new Hero(...)` внутри `Add` создал второй объект вместо добавления ссылки (вывод `80 и 100`); исправление — `probeList.Add(probeHero);`.

**Самостоятельный шаг:** подсчёт (`Health >= 120`) — `2` (Артём и Александр); самый здоровый — `Александр (150)`. Начальным значением берём `guild.Heroes[0]`, чтобы сравнивать с участником списка без создания фиктивного объекта. При одинаковом максимуме в `strongest` останется первый из них, так как используется строгое сравнение `>`.
